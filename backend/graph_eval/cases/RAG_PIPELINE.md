# 사내 문서 검색 RAG 구축 과정

지난주부터 사내 매뉴얼 검색용 RAG 구축 과정을 정리하고 있다. 전체 파이프라인은 랭체인으로 RAG를 구현하는 방식이다.

## 구성
- 문서는 PDF를 텍스트로 뽑은 뒤 청크로 나눈다. 청크 크기는 500토큰으로 정했다.
- RAG는 질문과 문서를 같은 공간에 놓기 위해 Embedding을 사용한다.
- 벡터 저장소는 FAISS를 쓴다. FAISS는 벡터DB의 한 종류로, 로컬 파일로 저장·로드할 수 있어서 재생성 비용을 아낄 수 있다.
- RAG는 검색 단계에서 FAISS를 사용해 상위 k개 청크를 가져온다.

## 로컬 LLM
폐쇄망 테스트 때문에 답변 생성은 Ollama로 돌린다. 랭체인은 Ollama와 연동해서 모델 호출부만 바꾸면 OpenAI와 교체할 수 있다.

## 남은 일
- 한국어 문서에서 검색 품질이 영어보다 떨어지는지 샘플 질의로 확인
- RAGAS로 faithfulness, context recall 비교
- k 값을 3, 5, 8로 바꿔 가며 실험
