# 팀 Git 작업 규칙

팀에서 쓰는 Git 작업 방식을 정리한다.

## 브랜치
- main에 직접 커밋하지 않고 기능 브랜치(feature branch)를 만들어 작업한다.
- 원격 저장소는 GitHub이고, GitHub는 Git에 의존해 동작한다. PR로 리뷰를 받은 뒤 병합한다.

## 충돌 줄이기
기능 브랜치를 오래 두면 병합 충돌(merge conflict)이 커진다. 작업 중에 main 기준으로 자주 rebase해서 병합 충돌을 해결한다.

## 커밋 전 검사
pre-commit을 설치해서 커밋할 때마다 ruff를 돌린다. pre-commit은 ruff와 연동되어 포맷과 린트를 자동으로 검사한다.

## 메시지
커밋 메시지는 한국어로, "유형: 요약" 형식을 따른다.
