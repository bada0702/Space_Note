# 지식 그래프 기반 RAG 설계

- 날짜: 2026-10-03
- 상태: 승인됨 (구현 계획 문서 검토는 사용자 요청으로 생략)

## 목표

AI 채팅의 '노트 RAG'가 질문에 쓴 단어가 노트에 글자 그대로 없어도, 개념 사이의 관계를 따라가 관련 노트를 찾아 답변 근거로 쓴다. 답변 아래에 근거 노트와 그 노트를 고른 관계 경로를 보여준다.

범위 밖: 성도(StarMap) 시각화 변경, 의미 검색(임베딩). 기존 `entities` / `tags` / `routes` 테이블과 키워드 분석(`analysis_status`)은 그대로 둔다 — 성도 항로가 사용한다.

## 1. 데이터 구조

| 테이블 | 컬럼 | 비고 |
|---|---|---|
| `concepts` | `id`, `name`, `norm` (UNIQUE), `type`, `created_at` | 모든 노트가 공유. 같은 `norm`은 하나의 개념 |
| `concept_aliases` | `norm` (PK), `alias`, `concept_id` | 같은 동의어는 먼저 등록된 개념을 따른다 |
| `note_concepts` | `note_id`, `concept_id`, `weight` (1~3) | PK(`note_id`, `concept_id`) |
| `relations` | `id`, `subj_id`, `pred`, `obj_id`, `note_id` | UNIQUE(`subj_id`, `pred`, `obj_id`, `note_id`). 나온 노트 수가 신뢰도 |

- 관계 종류(고정 5개): `사용한다`, `일종이다`, `일부이다`, `해결한다`, `관련있다`(기본값)
- 개념 종류(7개): `기술`, `도구`, `개념`, `문제`, `사람`, `조직`, `프로젝트` (그 외 값은 `개념`으로)
- `notes`에 `graph_status` (`idle` | `pending` | `done` | `failed`, 기본 `idle`)와 `graph_hash` (마지막 분석 본문의 해시) 추가
- 노트 재분석 시 그 노트의 `note_concepts` / `relations`만 교체하고, 어디에서도 쓰이지 않는 개념과 동의어는 정리한다. 노트 삭제 시에도 같다.

## 2. 추출

- 노트 생성/본문 변경 시 `graph_status = 'pending'`만 표시한다. 기존 노트는 `idle`로 시작해 사용자가 일괄 분석을 눌러야 처리된다.
- 백엔드 시작 시 작업자 스레드 하나를 띄운다. `pending` 노트 중 **마지막 수정 후 60초가 지난 것**을 하나씩 처리한다. 본문 해시가 `graph_hash`와 같으면 호출 없이 `done`.
- 처리 속도는 분당 최대 10개.
- 모델 `gemini-3.5-flash`, JSON 응답(`responseMimeType: application/json`):
  `{"concepts":[{"name","type","aliases":[],"weight"}],"relations":[{"s","p","o"}]}`
  - 개념 최대 15개, 관계 최대 20개, 관계는 뽑은 개념끼리만, 관계 종류는 5개 중에서만
  - 기술/제품명은 공식 영문 표기, 일반어("방법", "코드", "문제") 제외
- 본문은 앞 40,000자만 보낸다.
- 형식이 깨진 응답은 1회 재요청 후 `failed`. 429/500/503은 지수 백오프로 재시도.
- API: `POST /graph/rebuild` (보관되지 않은 전체 노트를 `pending`으로), `POST /graph/retry-failed`, `GET /graph/status` (상태별 개수)

## 3. 검색

검색어: 최근 사용자 발화 2개(기존과 동일).

1. **출발 개념**: 정규화한 질문 문자열에 개념 이름/동의어(2자 이상)가 포함되는지 검사. 영문·숫자로 된 이름은 단어 경계를 지킨다. 현재 열린 노트의 weight ≥ 2 개념을 0.5점으로 추가.
2. **확장**: 관계를 방향 무관하게 최대 2단계. 단계마다 ×0.5, 관계 가중치(`관련있다` 0.6, 나머지 1.0), 신뢰도 `1 + 0.2·log(나온 노트 수)`를 곱한다. 연결 50개 초과 개념은 더 넓히지 않는다(허브 차단). 단계마다 상위 30개 개념만 유지.
3. **노트 점수**: 그래프 점수 = Σ(개념 점수 × weight/3 × log(1 + 전체 노트 수/그 개념의 노트 수)). 키워드 점수는 기존 IDF 방식. 각각 최댓값으로 0~1 정규화 후 `0.6 × 그래프 + 0.4 × 키워드`, 상위 5개.
4. 출발 개념이 없으면 기존 키워드 검색 → 최근 노트 순으로 대체(기존 동작과 동일).
5. **근거 경로**: 노트마다 가장 크게 기여한 개념의 경로를 `'RAG' —사용한다→ '임베딩'` 형태로 기록. 키워드로만 뽑히면 `키워드 'FAISS' 일치`.
6. 발췌 1,200자는 질문 키워드와 경로 개념이 처음 나오는 위치 주변을 자른다.

## 4. 화면

- `/ai/chat` SSE: 답변 텍스트 전에 `data: {"sources":[{"id","title","path"}]}` 1회.
- `/ai/retrieve`: 기존 필드 유지 + `reason` 추가 (외부 aibot 호환).
- 채팅: 어시스턴트 답변 아래 '근거 노트 N개' 목록(기본 펼침, 접기 가능). 제목 클릭 시 노트를 편집 화면으로 연다. 경로는 작은 보조 글씨.
- 설정 화면 '지식 그래프': 상태별 개수(5초마다 갱신), [전체 다시 분석](예상 시간 확인 후 시작), 실패가 있으면 [실패한 노트만 다시 시도].

## 검증

- 단위 테스트: 추출 결과 병합(동의어 재사용, 재분석 시 교체, 고아 개념 정리), 동의어 매칭, 2단계 떨어진 노트 탐색, 허브 차단, 그래프 없을 때 대체 동작, SSE `sources` 이벤트, `/graph/*` API.
- 실제 비교: 질문 약 10개로 기존/신규 상위 5개 노트를 나란히 비교해 가중치를 조정.
