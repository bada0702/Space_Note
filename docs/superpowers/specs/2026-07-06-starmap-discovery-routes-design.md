# 미개척 항로 → 성도 항로선(우주선 왕복) 시각화

날짜: 2026-07-06
상태: 승인됨 (사용자 확인)

## 배경

- 미개척 항로 패널(`DiscoveriesPanel.tsx`)은 `norm`(정규화된 엔티티 이름) 기준으로
  엔티티를 공유하는 노트들을 텍스트 목록으로만 보여준다.
- 성도(`StarMapCanvas.tsx`)는 노트를 행성으로, 카테고리를 항성계로 그리지만
  노트 간 연결 관계는 전혀 표현하지 않는다.
- 목표: 미개척 항로에서 발견된 노트-노트 연결을 성도에서 행성과 행성을 잇는
  항로로 항상 시각화하고, 그 항로 위를 작은 우주선이 왕복하게 한다.

## 기능 1 — 백엔드: 노트 쌍 연결 엔드포인트

### `GET /discoveries/routes` (`backend/routers/search.py`, 인증 필요)

- `entities` 테이블을 `norm` 기준으로 그룹핑해 같은 `norm`을 공유하는
  서로 다른 노트들을 모두 쌍으로 묶는다 (기존 `discoveries()`와 같은 JOIN 패턴,
  norm이 빈 값/NULL인 엔티티는 제외).
- 한 쌍이 여러 엔티티를 공유해도 항로는 1개로 합치고, 공유 엔티티 이름은
  배열로 모은다.
- 쌍의 순서는 항상 `note_a < note_b`(문자열 비교, uuid 기준)로 정렬해
  중복 반환을 방지한다.
- 노트 하나당 연결 상한 20개(공유 엔티티 개수 많은 순)로 자른다 — 한 엔티티를
  아주 많은 노트가 공유할 때 조합 폭발 방지. 판정은 각 노트별로 독립적으로
  상위 20개를 뽑은 뒤 합집합(union)으로 최종 쌍 목록을 만든다 — 즉 한 쌍이
  두 노트 중 어느 한쪽에서라도 상위 20위 안에 들면 결과에 포함된다(한쪽만
  기준으로 잘라서 비대칭하게 빠지는 경우 방지). 이 상한은 응답에 드러내지
  않고 서버 로직 안에서만 적용.
- 응답 형식:
  ```json
  [
    {"note_a": "id1", "note_b": "id2", "shared_entities": ["Ollama", "Docker"]},
    {"note_a": "id1", "note_b": "id3", "shared_entities": ["Claude"]}
  ]
  ```
- 계산은 파이썬 인메모리 groupby로 처리(개인용 단일 사용자 앱 규모 — 노트 수
  수백~수천 수준 가정). 규모가 커지면 이후 SQL 집계로 옮길 수 있다.

### 프론트 API (`src/api/searchApi.ts`)

- `searchApi.discoveryRoutes(): Promise<DiscoveryRoute[]>` 추가.
- `src/types/index.ts`에 `DiscoveryRoute { note_a: string; note_b: string; shared_entities: string[] }` 추가.

## 기능 2 — 프론트: 성도에 항로 렌더링

### 데이터 로드 (`StarMapCanvas.tsx`)

- 씬 구성 effect(`[categories, notes, starMapFilter]`) 안에서 `/discoveries/routes`를
  1회 호출해 라우트 목록을 가져온다. 실패 시 콘솔에만 기록하고 항로 없이
  나머지 씬(행성/궤도)은 정상 렌더링한다.
- `note_a`/`note_b`가 현재 `visibleNotes`에 없는 경우(다른 카테고리 필터로
  숨겨진 노트) 해당 항로는 건너뛴다.

### 렌더링

각 항로마다:

1. 두 행성 메시의 **현재 위치**를 매 프레임 읽어 `THREE.CatmullRomCurve3`로
   완만한 곡선을 만들고, 옅은 색(두 행성 카테고리 색의 중간톤) `THREE.Line`으로
   배경에 그린다.
2. 그 곡선 위를 왕복하는 작은 우주선 메시(단순 콘 형태, 진행 방향으로 정렬)를
   추가한다. 진행 파라미터 `t`를 0→1→0으로 왕복시키며 완급 조절(ease)을 준다.
3. 두 행성이 계속 공전하므로, 항로 곡선과 우주선 위치 모두 **기존 `animate()`
   루프 안(`spinners.forEach` 갱신 지점)에서 매 프레임 재계산**한다.
4. 우주선 메시를 기존 `raycaster.intersectObjects` 대상에 포함시켜, 호버 시
   해당 항로의 `shared_entities`를 툴팁으로 보여준다(기존 행성 툴팁과 같은
   `Tooltip` 상태를 재사용하되 텍스트만 다르게).
5. 씬 정리(cleanup)에서 항로 곡선/우주선의 geometry/material도 이번 리뷰에서
   고친 `scene.traverse` 정리 로직에 포함되어 자동으로 해제된다(별도 처리 불필요).

## 성능/에러 처리

- `/discoveries/routes` 실패 시: 성도 자체는 정상 렌더링, 항로만 생략, 콘솔 에러만 남김.
- 공유 엔티티가 있는 노트가 없으면: 항로 없이 조용히 통과 (에러 아님).
- 노트당 20개 상한으로 항로/우주선 총 개수를 억제해 프레임 드랍 방지.

## 테스트

- 백엔드: pytest로 `GET /discoveries/routes` 검증 — 엔티티 공유 시 쌍 생성,
  공유 없으면 미생성, 쌍 순서 정렬로 중복 없음, 노트당 20개 초과 시 상위
  20개만 반환.
- 프론트: 이 저장소에 아직 프론트 테스트 프레임워크가 없어 자동 테스트는
  작성하지 않는다. 브라우저에서 두 노트에 공통 엔티티를 만든 뒤 성도에서
  항로선과 왕복 우주선, 호버 툴팁을 수동으로 확인한다.
